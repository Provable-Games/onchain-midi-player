# Beast reference consumer

`BeastLikeNft` is a standard OpenZeppelin Contracts for Cairo 4.0.1 ERC721 (`ERC721Component` with `ERC721MixinImpl`, and `SRC5Component`), so explorers and marketplaces recognize it: `supports_interface` reports SRC5 (`0x3f918d17e5ee77373b56385708f855659a07f75997f365cf87748628532a055`), IERC721 (`0x33eb2f84c309543403fd69f0d0f363781ef06ef6faeb0131ff16ea3175bd943`) and IERC721Metadata (`0xabbcd595a567dce909050a1038e055daccb3c42af06f0add544fa90ee91f25`). Its name is `Beast-like Example` and its symbol `BEASTX`. The constructor takes `(tinysynth_class_hash, recipient)`: it checks the TinySynth class's engine and version, then mints tokens 1–4 to `recipient`. Ownership, transfers and approvals are OpenZeppelin's. The metadata `token_uri` (and camelCase `tokenURI`) is the contract's `ERC721TokenURITrait` implementation in place of OpenZeppelin's base-URI one: it returns the complete NFT-owned document below, and reverts with `ERC721: invalid token ID` for a token that does not exist. `tinysynth_class_hash()` returns the stored class hash. OpenZeppelin is a dependency of this example only; the TinySynth class has none.

`mint(to, token_id, name, tier)` is a testing convenience, not a pattern for production NFTs: anyone can mint any unminted token id as a Beast with a name in the Beasts charset (1–31 bytes of A-Z a-z 0-9, space, `'`, `-`) and a tier from 1 to 5. A minted Beast is rendered like tokens 1–3, with the sample loop and reverb from its tier. Minting an existing token reverts with `ERC721: token already minted`; an invalid name or tier, or the zero address, also reverts. The deployment recorded in [`deployments/sepolia.json`](../../deployments/sepolia.json) has token 5 minted this way as `Kraken`, tier 4 (`MINTED` in [`scripts/reference.mjs`](scripts/reference.mjs)). The live token 5's `token_uri` matches the length and SHA-256 the tests pin (`minted_token_uri_digest`).

The NFT owns its complete document, SVG image, styles, title/favicon, controls, anchoring, controlled inline SVG timelines and background/media-session policy. Its generated fragments are the [`owned_assets`](../owned_assets) package, separate from every TinySynth class constant; [`stress_nft`](../stress_nft) and the root package's tests use the same package. `assembly.cairo` directly splices standalone library fragments and runtime metadata/art/data using an encoder compiled into the consumer.

Metadata and initial document art use a complete encoded `<img>`. Only this contract's own renderer opts into `data-trusted-art="inline-svg"`: bootstrap imports trusted Genesis art as inline SVG, which animates from page load. Generic composition defaults to isolated images for arbitrary/community SVG. A failed library still leaves ordinary art visible.

The NFT-owned ▶/❚❚ button suspends/resumes the AudioContext through the public player API. Its size is a page setting, not code: the stylesheet's `--play-min` and `--play-max` clamp every diameter, the one the art's `data-play-anchor` asks for with S (S times the art's scale) and otherwise a 48 px default (an anchor without S, or the corner button when the art has no anchor). This example ships 16–128 px, so a button anchored with S stays proportional to the card (the Beasts card's `"235 58 24 top-right"`, 24 units or about 10% of the card's width, draws about 22 px on a phone-sized card and about 40 px on a desktop-sized one) and never drops below 16 px; equal limits fix the size. `--play-target` (44 px) is the touch target, an invisible circle around a smaller button. Art sync is a small reference to copy, [`art_sync.js`](art_sync.js): the art is never scheduled, only seeked to the music's position when the player announces a moment. Trusted inline SVG runs freely until the music is audible (the initial pass event, or the player's clock if that event never reaches it), then is seeked there and at each later pass, latency change and resume; where it belongs is read from `getPlayStatus()` each time. A pause stays audible until its suspend completes: the art runs on, then freezes at the player's held audio position. Stop releases it to run freely, without a rewind. An isolated `<img>` can't be paused or seeked: it is restarted at each pass with a freshly decoded copy, up to one decode late. On pause it freezes: the page cannot read the frame an image shows (canvas `drawImage` gets a GIF's first frame), so it works out that frame from the AudioContext time since the image started (`audioElapsedMs`, which a late-noticed pause or a latency change cannot move, plus any suspension the image played through unfrozen) and its GIF's own delays, and shows the art with the GIF replaced by a PNG of that frame (`stillSvg`: each frame up to it is cut out as a one-frame GIF the browser decodes, and drawn on a canvas with the GIF's disposal methods); resume restarts the art from its first frame. Art without a GIF, and any other animation in the image, keeps moving; a hidden page makes the still once it is visible. Only the latest pause's still is shown; a GIF that has played its loop count shows its last frame. Under `prefers-reduced-motion` (read once) the bootstrap holds the image still from the start, on a still of its first frame, through play, pause and resume, as the notes stand still. In headless Firefox 155 (Playwright) a GIF inside an SVG image showed only its first frame, so there the art never moved and the still changed nothing visible. Optional notes, the token's MIDI as a piano roll behind the art ([`player/notes.js`](../../player/notes.js)), share the helper's clock and transport controls. This example ships them as their own NFT-owned fragment, [`fixtures/notes.html`](fixtures/notes.html) (generated by `npm run gen:segments`, checked by `npm run check:segments`; never part of the class), spliced after the data and before the bootstrap. The bootstrap (`startNotes` in [`ui.js`](ui.js)) draws them only when that fragment is present and the art's root `<svg>` has a `<rect>` child marked `data-notes-bg` (here the art frame's background rect) with plain numbers for its geometry: it reads the notes' box from that rect and their units from the root `viewBox`, shows the page's copy of the art with that background cut out (the metadata `image` is untouched), puts the canvas just behind the art and drives it with `syncSvgToMusic` (with no root for an `<img>`, which still restarts at each pass). An `<img>` switches to the cut-out copy only once an off-screen copy has decoded it; if it cannot, the art keeps its own URL and the notes are removed, and restarts begin once either has happened, so they copy what is showing. Without the fragment or the marker, or if the notes fail, the page has no canvas and plays as before. This example's opaque sprite is 80 x 80 in its 128 x 128 frame, so the notes show around it. No dimming. The read-only `OnchainArtMonitor` samples drift and latency events without continuous correction. Its 17 ms display lead is the provisional lab setting, pending [#52](https://github.com/Provable-Games/onchain-midi-player/issues/52) hardware evidence.

The silent six-second WAV, iOS playback session, bitmap artwork and media handlers remain NFT policy. The WAV only keeps the media controls alive: the bootstrap publishes one pass of the music as the media session's position state (`positionState` in [`ui.js`](ui.js)) at each pass and state change, so the notification shows the pass's length and position, not the WAV's 6 s. Media play resumes; both media pause and media stop pause, as explicitly selected in the prototype. Public player stop resets the score. Blocked blob media permits ordinary audio and pauses on hiding. Real mobile/route/lock-screen acceptance remains #52.

The independent multi-provider Cairo fixture lives in root tests: TinySynth supplies loader/combined player/data and `FixtureProvider` supplies a tiny named-export library. NFT code uses that export after readiness, and a dependent test block proves ordering. No p5.js implementation, integration or benchmark is included.

```sh
scarb build
snforge test
node scripts/gen_fixtures.mjs
node --test scripts/*.test.mjs
node scripts/browser_check.mjs
```

Tokens 1–3 have complete independent JS goldens; token 4 uses unchanged 22,733-byte Warlock art, 3,716-byte MIDI and reference sounds for full-size parity/measurement. That historical SVG embeds an animated GIF; neither SVG timeline control nor an image restart controls the GIF image clock, so use SMIL sprite animation for motion synced to the music. Synchronization acceptance uses outer and nested SVG/SMIL animations. `tests/naive.cairo` constructs equivalent complete HTML and performs runtime full-page encoding; direct splicing is the efficient recommended integration, while consumer re-encoding remains supported.
